[[cha:mesa_modbus]]

= Mesa Modbus =

== Status ==

The `mesa_modbus` driver and its `mesa-modcompile` compiler have been removed.

Modbus over a Mesa PktUART port is now provided by `hm2_modbus`, which covers
the same devices and does so without a compile step.
See link:../man/man9/hm2_modbus.9.html[hm2_modbus(9)].

== Why it changed ==

`mesa_modbus` worked by generating C from a `.mod` description of the device,
compiling it, and installing the result as a driver.
That required a toolchain on the machine running LinuxCNC, and produced one
driver binary per device.

`hm2_modbus` is configured instead by a _Modbus Command Control Binary_ (MBCCB)
file, which is data rather than code.
One driver serves every device, the configuration is read when the driver
loads, and nothing has to be compiled on the control.

== Moving an existing configuration ==

Describe the device in an MBCCB source file, compile it to `.mbccb` with
link:../man/man1/mesambccc.1.html[mesambccc(1)], then load the driver with the
port and the file:

----
loadrt hm2_modbus ports="hm2_7i96s.0.pktuart.0" mbccbs="/path/to/device.mbccb"
----

`ports` takes a comma separated list of PktUART HAL names and `mbccbs` a
matching list of MBCCB file paths; use absolute paths.
link:../man/man9/hm2_modbus.9.html[hm2_modbus(9)] documents the remaining
parameters.

The channel descriptors that used to be written as C in a `.mod` file
(`hm2_modbus_chan_descriptor_t`) have direct equivalents in the MBCCB format,
so an existing `.mod` file is a useful starting point for the rewrite.

== If you need hand-written C ==

The one thing `.mod` files allowed that MBCCB does not is arbitrary C for a
device that fits no ordinary pattern.
Write that as a normal out-of-tree component instead: the
<<cha:hal-component-generator,HAL Component Generator>> chapter describes
building one with `modcompile` and linking it against the cmod headers.
